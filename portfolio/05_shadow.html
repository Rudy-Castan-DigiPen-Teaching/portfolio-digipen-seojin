Project Shadow Mapping

3D Graphics

Project Overview

In this project, I implemented a real-time Shadow Mapping system integrated into an interactive 3D graphics demo. The primary purpose was to model a perspective light source as a camera, capture the scene's depth from the light's point of view, and use that depth map to render realistic, dynamic shadows on the objects. The project aimed to achieve a seamless multi-pass rendering pipeline compatible with both Windows (x64) and Web (WebGL) platforms, featuring adjustable parameters for fine-tuning shadow accuracy, frustum visualizers, and atmospheric effects like exponential fog.

Tasks Completed

  • Build & Demo Setup: Integrated the starter files into the workspace structure, modified the C++ build configurations in CMake, and registered the new interactive demo under the global demo manager.
  • OpenGL Texture Enhancements: Upgraded the Texture wrapper class to support depth textures (supporting various bit depths like 16, 24, 32, and 32-bit float). Configured OpenGL parameters (GL_TEXTURE_COMPARE_MODE as GL_COMPARE_REF_TO_TEXTURE and GL_TEXTURE_COMPARE_FUNC as GL_LEQUAL) to enable hardware-accelerated depth comparison.
  • FrameBuffer Management: Created the FrameBuffer class to handle frame buffer object (FBO) allocation, texture attachments (color and depth), and validation of complete framebuffer status.
  • Camera Matrix Calculations: Programmed the Camera class coordinate conversions to generate a custom ViewMatrix (world space to camera space) and a ToWorldMatrix (camera space to world space) analytically using vector cross/dot products, bypassing expensive generic matrix inversion calls.
  • Trefoil Knot Mesh Generation: Programmed a custom parametric mesh generator for 3D trefoil knots, utilizing camera-like frame sweeps along the curve to generate vertices, normals, and texture coordinates.
  • Two-Pass Shadow Mapping Logic:
    • Pass 1 (Depth recording): Guided the light camera perspective into the depth buffer, utilizing polygon offsets (glPolygonOffset) and custom face-culling switches to minimize visual artifacts.
    • Pass 2 (Color rendering): Rendered the scene from the spectator camera, mapping coordinates to biased shadow space and reading occlusion states using sampler2DShadow and textureProj.
    • Debugging Visuals: Implemented visual toggles to render the light’s camera frustum in world space (transforming the NDC cube by the inverse projection and camera world matrix) and to overlay the depth map using a screen quad.
  • Shader Programming: Completed GLSL code for shadows.vert and shadows.frag to handle lighting, hardware shadow filtering, gamma correction (1/2.2), custom checks to disable shadow casting behind the light source, and radial exponential fog.

Reflection

Challenges Faced:

  • Shadow Acne & Precision Artifacts: Initial shadow rendering suffered from severe shadow acne (concentric banding on surfaces) due to finite depth buffer precision. I solved this by configuring glPolygonOffset during the depth map recording pass and enabling front-face culling so that back faces were drawn, leaving the front faces artifact-free.
  • Behind-the-Light Shadow Bleeding: Objects situated behind the perspective light source were receiving incorrect shadow mapping projections due to the mirroring nature of perspective division. I implemented a conditional check in the fragment shader to examine the shadow-space homogeneous coordinates (z < 0.0) and override the shadow coefficient to 1.0 (fully lit) for fragments behind the light plane.
  • Toolchain Compilation Discrepancies: While compiling the project for WebGL using the Emscripten compiler (Clang), the compiler suffered segmentation faults when processing implicit std::array class template argument deductions (CTAD) for initialization lists, and threw strict errors on implicit sign conversions. I addressed these by explicitly typing template parameters (e.g., std::array<DemoMetaData, 4>) and applying explicit static_cast for enum-to-signed comparisons.

Lessons Learned:

  • Gained a solid, intuitive understanding of projection space mapping, particularly how to construct matrices to convert clip space coordinates back to world space for frustum visualization.
  • Mastered multi-pass rendering pipelines using FrameBuffer Objects (FBOs) and depth-sensitive sampler types in GLSL (sampler2DShadow with textureProj).
  • Learned the importance of strict type safety and warning compliance when building cross-platform projects targeting multiple compilers (MSVC vs. Clang/GCC).
